# أداة Backtesting — النسخة 0.1

مشروع Python مستقل لاختبار تسلسل **4H BOS → Premium/Discount → 15m CHOCH → Fibonacci 0.618 → تأكيد شمعة → دخول**.

**المشروع جاهز للتشغيل التجريبي. القواعد غير المحسومة في وصف الاستراتيجية تحتاج اختيارك قبل اعتبار النتائج اختبارًا لاستراتيجيتك الفعلية.** لم تُعتمد اختيارات المثال كقواعد لك؛ الملف `configs/strategy.unresolved.json` يرفض التشغيل حتى تعبئة الخيارات. اقرأ `docs/DECISIONS_AR.md`.

## تشغيل سريع على Windows

1. فك ضغط الملف كاملًا.
2. يلزم وجود Python 3.11 أو أحدث. لا تحتاج مكتبات إضافية أو حساب تداول أو إنترنت.
3. افتح `run_demo.bat` بالنقر مرتين. يشغّل الاختبارات، ثم الحالات الست، ويفتح التقرير الأول.
4. التقارير الأخرى موجودة داخل `outputs`؛ افتح `report.html` في أي مجلد حالة.

تم اختبار Python نفسه على Linux / Python 3.12؛ ملف تشغيل Windows مرفق ولم يُختبر على جهاز Windows في هذه الجلسة.

على macOS / Linux:

```bash
sh run_demo.sh
```

ومن الطرفية، وأنت داخل مجلد المشروع:

```bash
python -m unittest discover -s tests -v
python -m mtf_backtest demo
```

## تشغيل CSV الخاص بك

املأ نسخة من `configs/strategy.unresolved.json` بخياراتك أولًا، ثم:

```bash
python -m mtf_backtest run --csv data/your_15m.csv --config configs/my_strategy.json --out outputs/my_run --all-charts
```

عرض تسلسل صفقة ورسمها:

```bash
python -m mtf_backtest run --csv data/long_win.csv --config configs/demo.json --out outputs/review --debug-trade 1 --plot-trade 1
```

ولعرض أسماء الإعدادات وقيمها المدعومة:

```bash
python -m mtf_backtest choices
```

## صيغة البيانات

```csv
timestamp,open,high,low,close,volume
2025-01-06T00:00:00+00:00,100,102,99,101,500
2025-01-06T00:15:00+00:00,101,103,100,102,550
```

- البيانات الأساسية في هذه النسخة **15 دقيقة فقط**. لا يُخمَّن فريم الملف.
- الافتراضي `timestamp_label: open`: الوقت هو بداية الشمعة، ويصبح OHLCV متاحًا بعد 15 دقيقة. يمكنك تحديد `close` إن كانت بياناتك مؤرخة بوقت الإغلاق.
- `source_timezone` لتفسير الأوقات دون إزاحة؛ `timezone` لمحاذاة 4H وعرض الرسم. كل السجلات الداخلية وCSV النتائج بتوقيت UTC مع الإزاحة، فلا تختلط المناطق الزمنية.
- `h4_anchor_minutes: 0` يعني بداية اليوم المحلي. عند UTC تكون الشموع 00:00–04:00، 04:00–08:00… لا تنسب شمعة مكتملة إلى وقت بدايتها بوصفه وقت القرار.
- كل شمعة 4H تحتاج 16 شمعة 15m متصلة زمنيًا، وإغلاق الشمعة السادسة عشرة. الشموع الجزئية أول الملف وآخره أو ذات الفجوات لا تُصدر.
- لا فرز خفي، ولا تعبئة تلقائية للأسعار. التكرار، الترتيب غير الصحيح، OHLC غير المتسق، القيم غير المحدودة والحجم السالب أخطاء واضحة.
- `data_gaps: error` افتراضيًا. لاستيعاب إغلاق السوق في عطلة نهاية الأسبوع اختر `allow` صراحة؛ تُسقط حاويات 4H غير المكتملة، وتستخدم الـPivots خمس **شموع موجودة فعلًا** عبر الفجوات، دون توليد شموع وهمية.
- المناطق ذات DST: اجلب وقتًا بإزاحة صريحة عند تكرار/اختفاء الساعة؛ لا نخمن معنى الوقت المحلي الملتبس. حاويات 4H أربع ساعات فعلية من مرساة اليوم المحلي؛ قد تُسقط حاوية عند انتقال DST. للمقارنة الدقيقة مع وسيط، طابق محاذاة 4H وتوقيت ملفه أولًا.
- الأسعار أرقام عشرية بوحدات الأصل. `stop_buffer` مسافة سعر مطلقة، وليست تلقائيًا نقطة أو pip. لا تقريب إجباري لحجم tick لم تحدده.

## المخرجات

| الملف | المحتوى |
|---|---|
| `trades.csv` | السجل الكامل، بما فيه الصفقات المفتوحة والغامضة |
| `summary.json` | كل مؤشرات الأداء المطلوبة بوحدة R |
| `report.html` | تقرير عربي قابل للفتح محليًا |
| `events.jsonl` | أوقات تأكيد Pivots وBOS والمنطقة وCHOCH واللمس والتأكيد والخروج |
| `debug_trade_N.txt` | التسلسل الخاص بالصفقة N |
| `trade_N.svg` | شموع، الاتجاه، CHOCH، الموجة، 0.618، اللمس، التأكيد، الدخول والوقف والهدف |
| `run_manifest.json` | الإعدادات الفعلية وإصدار المحرك وبصمة SHA-256 للبيانات وعدد شموع 4H المستبعدة |

الرسوم SVG مستقلة ودقيقة وقابلة للتكبير. يتوفر الرسم عبر `--plot-trade N` أو `--all-charts`؛ العرض لا يؤثر على قرارات المحرك، ويمكنه إظهار شموع بعد الصفقة لأجل المراجعة فقط.

مطابقة أسماء السجل لطلبك: `bos_time_4h` = 4H BOS time، `direction_4h` = 4H direction، `zone_entry_time` = وقت دخول Premium/Discount، `choch_time_15m` = 15m CHOCH time. باقي الحقول بأساميها المباشرة، ويضاف `trade_id` و`setup_id` وأوقات بداية/نهاية الموجة والدخول.

## الإحصاءات والتعامل مع الغموض

- RR الافتراضي **1:2 في المحرك وفي كل حالات المثال الست**. تغييره عبر `risk_reward`؛ مثال 1:1.5 يكتب `1.5`.
- `confirmation_close` هو الدخول الافتراضي. يتوفر أيضًا `next_open` ويعاد حساب الهدف من سعر الافتتاح الفعلي. قيمة `limit` ترفض برسالة صريحة حتى تُحدد قواعد السعر والانتهاء والتنفيذ.
- الوقف التجريبي الوحيد حاليًا `touch_extreme` مع هامش موجب أسفل/أعلى شمعة اللمس. إضافة قواعد وقف أخرى تكون في وحدة `backtest/risk.py`.
- الصفقة التي تلمس SL وTP في الشمعة نفسها وبداية الشمعة بينهما: `AMBIGUOUS_INTRABAR`، دون سعر خروج مفترض أو R مختلق.
- عند افتتاح الشمعة خارج حد الوقف/الهدف، موضع الافتتاح معروف قبل مدى الشمعة: حسب `gap_execution` إمّا سعر الافتتاح، أو `GAP_UNRESOLVED`. في تنفيذ الافتتاح قد تكون الخسارة أكثر من ‎−1R أو الربح أكثر من الهدف.
- `OPEN` عند انتهاء البيانات يبقى مفتوحًا؛ لا إغلاق مصطنع في آخر سعر. أمر `next_open` في نهاية الملف يبقى معلقًا ولا يسجل صفقة قبل وصول شمعة لاحقة.
- Total Trades يشمل كل الدخولات. Wins وLosses وWin Rate وProfit Factor وExpectancy والمتوسطات وTotal R تحسب من **الصفقات المحسومة فقط**؛ يعرض عدد الحالات المستبعدة منفصلًا.
- Average Loser سالب. Profit Factor = مجموع R الموجب ÷ القيمة المطلقة لمجموع R السالب؛ `Infinity` إذا وجدت أرباح ولا خسائر؛ `null` عند غياب نتائج محسومة.
- Max Drawdown انخفاض الرصيد التراكمي المحقق من قمته بوحدة R؛ ليس انخفاض رأس المال أو التعرض العائم. الترتيب بوقت ملاحظة الخروج، وتُجمع المخارج ذات الوقت نفسه. التسلسلات المتتالية تستخدم `trade_id` لكسر تعادل وقت الخروج لعدم معرفة الترتيب داخل الشمعة.
- هذه نتائج **إجمالية قبل الرسوم والسبريد والانزلاق**؛ لم يحدد وصفك بيانات التكلفة. الدخول عند إغلاق التأكيد محاكاة سعرية كما طلبت، وليس ضمانًا لإمكانية التنفيذ بذلك السعر في السوق.

## منع استخدام المستقبل

المحرك يمر على شموع 15m المكتملة واحدة واحدة. Pivot الشمعة المركزية لا يظهر إلا عند إغلاق ثاني شمعة لاحقة. اتجاه 4H الجديد لا يُستخدم لتفسير نطاق شمعة 15m التي سبقته داخل شمعة BOS؛ يبدأ فحص المنطقة من الشمعة التالية.

عند تزامن إغلاق الفريمين: تنفذ أوامر الافتتاح الملتزم بها، ثم تحسم الصفقات القائمة، ثم تؤكد 4H وتطبق BOS الجديد، ثم تؤكد Pivots 15m وتفحص الإعداد. تحديث أقصى مدى 4H المستمر يسري على الشموع التالية فقط. كل الأوقات في سجل الأحداث هي وقت توفر المعلومة، ولا يعاد رسم الماضي.

اختبارات المنع تشمل مقارنة حالة المحرك عند **كل واحدة من 160 نقطة قطع** مع حالة التشغيل الكامل عند النقطة نفسها في الاتجاهين (320 مقارنة)، وتغيير أسعار المستقبل مع إثبات ثبات الماضي. هذا دليل اختباري على الحالات المغطاة، لا ادعاء إثبات رياضي لكل مسار بيانات ممكن.

## هيكل المشروع

| المجلد | المسؤولية |
|---|---|
| `mtf_backtest/data` | قراءة CSV والتحقق وتجميع 4H |
| `mtf_backtest/structure` | Pivots وكسور الإغلاق |
| `mtf_backtest/strategy` | المنطقة، الموجة، Fibonacci، اللمس والتأكيد |
| `mtf_backtest/backtest` | التوقيت والتنفيذ والوقف والهدف |
| `mtf_backtest/reports` | الإحصاءات والتصدير والرسم والتتبع |
| `tests` | اختبارات مستقلة دون اعتماديات خارجية |
| `configs` | إعدادات المثال وإعدادك غير المحسوم |
| `data` | ستة ملفات صغيرة، كل ملف 160 شمعة مصطنعة |
| `outputs` | نتائج تشغيل فعلية للحالات المصطنعة |
| `docs` | نقاط القرار وتقرير التحقق |

لا توجد FVG أو Order Blocks أو RSI أو EMA أو فلاتر حجم أو جلسات أو أخبار. الحجم يُقرأ ويجمع فقط ولا يؤثر على الدخول.
